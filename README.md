# OPGAME

A from-scratch third-person open-world game framework written in Rust.

The project is developed around original code and project-owned assets. Commercial games, characters, brands, logos, sounds, textures, models, and other proprietary assets are not part of the project.

## Current Features
- **Resizable game window**
- **Third-person offset camera** with mouse look and zoom
- **Player movement** relative to camera heading
- **Starter world layout** with roads and city blocks
- **External GLB model loading**
- **Player entity** with health, weapons, and movement physics
- **NPC, vehicle, combat, mission, UI, and audio systems** ready to be expanded
- **OpenGL renderer foundation** that runs on Windows, Linux, and macOS

## Asset Policy

Only assets that we created ourselves or have explicit permission/licenses to redistribute should be committed to this repository.

Do not add:
- ripped or extracted game assets
- proprietary characters or character models
- proprietary vehicles or vehicle models
- copyrighted game textures, sounds, animations, maps, or fonts without redistribution rights
- logos, trademarks, or branding copied from other games or companies

References to other games may be useful during private design discussion, but the repository should describe the project's own mechanics and assets without presenting another game's identity as part of OPGAME.

Before adding a third-party asset, record its source and license/permission in the repository documentation and verify that redistribution is permitted.

## Building

For normal development:

```bash
cargo build --release
cargo run --release
```

For a portable game directory containing the executable and external assets:

```bash
python tools/build.py
```

The script builds the release binary with Cargo and creates:

```text
dist/
  opgame(.exe)
  assets/
    models/
      player.glb
    fonts/
      ...
```

The game reads models and other runtime assets from the `assets` directory beside the executable. Models are **not** compiled into the executable. This means replacing `assets/models/player.glb` does not require rebuilding the Rust binary.

During development, the same assets are kept under `data/` in the repository. The runtime asset resolver uses `data/` for `cargo run` and `assets/` beside the executable for packaged builds.

The OpenGL context is created with glutin, so the same code builds and runs on Windows (WGL), Linux (GLX/EGL, X11 and Wayland), and macOS (CGL).

On Debian/Ubuntu the X11 and OpenGL development headers are needed:

```bash
sudo apt-get install libx11-dev libxkbcommon-dev libgl1-mesa-dev
```

The renderer currently uses a compatibility-profile OpenGL 2.1 context. The bindings for those entry points are generated at build time by `build.rs` (`gl_generator`) and loaded through glutin's `get_proc_address`.

A TrueType font is needed for on-screen text. The packaged build looks in `assets/fonts/` first and then falls back to platform system fonts. Any font committed to the repository must have redistribution rights compatible with the project.

## Controls
- **W/A/S/D** - Move relative to camera
- **Mouse** - Orbit camera
- **Mouse wheel** - Zoom in/out
- **Space** - Jump placeholder
- **Shift** - Sprint
- **Left mouse / F** - Fire weapon
- **R** - Reload
- **1/2/3** - Select weapon
- **P** - Pause
- **ESC** - Exit game

## Architecture

The project is organized as follows:

- `main.rs` - Entry point and event loop
- `game.rs` - Main game logic and state management
- `player.rs` - Player entity and stats
- `camera.rs` - Third-person offset camera with view/projection matrices
- `world.rs` - World layout, roads, buildings, time, and weather
- `entity.rs` - Base entity trait and world objects
- `renderer.rs` - OpenGL rendering backend
- `model.rs` - Runtime GLB model loading and immediate-mode drawing
- `assets.rs` - Runtime asset path resolution
- `gl.rs` - OpenGL compatibility bindings generated by `build.rs`
- `npc.rs` - NPC and AI state management
- `vehicle.rs` - Vehicle simulation
- `combat.rs` - Combat system
- `physics.rs` - Physics helpers
- `mission.rs` - Mission system
- `ui.rs` - HUD/UI state
- `sound.rs` - Audio system foundation
- `tools/build.py` - Release build and portable runtime assembler

## Next Steps

The next major rendering milestone is to replace the immediate-mode prototype geometry with shaders and vertex buffers. After that, the starter world can grow into a streamed world with models, textures, collision, NPCs, and vehicles.

## Dependencies

- **winit** - Window management and events
- **glutin/glutin-winit** - Cross-platform OpenGL context, surface, and proc address loading
- **gl_generator** - Build-time OpenGL compatibility bindings
- **glam** - Math library (vectors, matrices)
- **serde** - Serialization (for saving/loading)
